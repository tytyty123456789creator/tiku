出货箱：把收成就地卖成钱

玩家在田边放一个箱子，作物投进去，价格按当天行情算，金币到账，出一张收据。 就这样。剩下的问题是服主要定价、要限速、要留流水，那部分下面都写了。

玩家视角

用一个箱子卖东西，五步

这一段可以直接抄进你服的帮助文档，玩家看一遍就懂，不需要额外解释。

01

拿到出货箱。管理员发放，或者按服务器配方合成。

02

放在自家田边、棚子里，或者仓库门口。位置随你。

03

蹲下右键绑定。绑定之后这个箱子归你，别人动不了。

04

把作物丢进去。已定价的会被收，没定价的留在箱里。

05

等结算。立刻结算就当场到账，定时结算到点一起给，附一张收据。

箱子界面右下角那本书是收据，写着这一轮每样东西卖了多少件、单价多少、进账多少。 想先看行情，打 /sellbox prices，或者点箱子界面里的信息格。

指令手册

三条给玩家，其余都是你的

主命令 /sellbox，别名 /sb。按使用者分了四组，点标签切换。

指令作用权限
/sellbox prices打开今日收购价。按种类排，同种作物的普通、银星、金星挨在一起，带分页。sellbox.use
/sellbox log [页码]查自己的交易流水，每页 10 条，倒序。sellbox.use
/sellbox pending看有没有离线期间没发下来的钱。有的话上线会自动补。sellbox.use
/sellbox help列出所有子命令。玩家打错东西时会看到这个。—

玩家其实不需要指令。放箱子、投东西、看界面就够了，指令只是留给想查账的人。

指令作用权限
/sellbox give <玩家> [数量]直接给玩家出货箱物品。数量默认 1，上限受 box.max-per-player 约束。sellbox.admin
/sellbox list <玩家>列出这个玩家名下所有箱子，含世界与坐标。排查"箱子被谁占了"从这开始。sellbox.admin
/sellbox log <玩家> [页码]查任意玩家的流水。对账、查刷钱、处理纠纷都用这个。sellbox.admin
/sellbox pending [玩家]查待补发队列。不填玩家就是全服。sellbox.admin
/sellbox total <玩家>看这名玩家的累计卖出、今日已用、上限、剩余，以及四档阶梯里他站在哪一档。sellbox.use
/sellbox total <玩家> 5000000把累计卖出直接设成 500 万。设的是绝对值，之后他继续卖还会往上加。sellbox.admin
/sellbox total <玩家> +500000在当前基础上加 50 万。带 + 或 - 都按增量算，用来做补偿或扣罚。sellbox.admin
/sellbox top [页数]成交排行，按累计净额排。做榜单、做周报都行。sellbox.admin
/sellbox reload重载 config、价格表、文案。改完配置就打这个，不用重启。sellbox.admin
/sellbox config check打印当前生效的模块开关与关键参数。排查"为什么没结算"从这开始。sellbox.admin

total 改的是"累计卖出净额"，也就是决定日额度档位的那个值。 它不动流水日志，只记一个差值，对账的时候流水仍然干净。

指令作用权限
/sellbox setprice <单价>给手里的物品定价。写进 prices.yml，立刻生效。sellbox.admin
/sellbox setprice <单价> <物品id>给指定 id 定价，不用手持。适合批量调某一类作物。sellbox.admin
/sellbox pricing打开定价表。可搜索、可批量、可排序，比手改 yml 快。sellbox.admin
/sellbox prices以玩家视角看今日实价，含季节倍率与销量折价。定完价用它自查。sellbox.use

定价口径建议只留一个：按"玩家一分钟能产出多少金币"定，别按"这东西看起来值多少"定。 前者能直接跟你服里刷怪塔、挖矿、钓鱼的时薪对齐，后者定完一定会漏。

指令作用
/sellbox debug fill <x y z> <id> <数量>往指定坐标的箱子里塞货。测价格、测结算不用真的去种。
/sellbox debug sell <x y z>立刻结算这一个箱子。验证"到点会不会真的给钱"。
/sellbox debug quote <x y z>只算价不结算，打印每件物品的单价与合计。核价用。
/sellbox debug seasonfactor <季节> <id>查某个物品在某季节的倍率。确认 0.8 / 1.2 到底命中没命中。
/sellbox debug decay <id>查这个物品今天卖了多少、当前折价系数、全服排名。
/sellbox debug setseason <季节> [世界]临时改季节，测换季逻辑用。测完记得改回来。
/sellbox debug itemname <id>查这个 id 解析出的显示名，顺带打印词条数量。名字显示不对先跑这个。
/sellbox debug place <x y z> [owner]在指定坐标放一个箱子。清理残留记录、补回被误删的箱子都行。
/sellbox debug remove <x y z>移除箱子并释放绑定名额。
/sellbox debug bind <x y z> <玩家>强制把箱子绑给某个人，处理"箱子没主人"的情况。
/sellbox debug receipt <x y z>重新生成收据书，玩家弄丢了可以补。
/sellbox debug deposit <玩家> <金额>走经济插件打钱，确认 Vault 通路是否正常。
/sellbox debug paypending <玩家>手动把待补发队列结清。
/sellbox debug balance <玩家>查余额与待补发笔数。排查"钱没到账"的第二步。

调试指令不写流水，也不动玩家额度，放心用。

服主视角

价格是怎么算出来的

一次结算的价钱是四层乘出来的。知道顺序，调参数时就知道该动哪个。

BASE

基础价

prices.yml 里那一条。这是你唯一需要认真定的数字，后面三层都是修正。

items: customcrops:onion: 420
SEASON

季节倍率

当季 0.8，反季 1.2。规则写在 season.categories，match 支持通配，一条 customcrops:onion* 同时盖住普通、银星、金星，不用写三遍。

当季 ×0.8　反季 ×1.2　无季节作物 ×1.0
DECAY

销量折价

同一样东西当天卖得越多，单价越低，到下限为止。这是压住大农场无限出货的那一层，也是让玩法从堆地变成轮作的那一层。

每件 −0.1%，下限 70%（rate-per-item / min-factor）
TAX

税与额度

结算扣 5% 税，再计入当日额度。额度是阶梯的：卖得越多，上限越高。超出部分两种处理，停或者允许透支，建议停。

5万 → 20万 → 50万 → 100万（按累计净额解锁）
WHEN

什么时候给钱

instant 是投进去立刻卖；scheduled 是箱里先囤着，游戏内到点一次性结算。定时模式给农业服一个天亮收账的节奏，也顺手把结算压到你挑的时间点，方便观察。

scheduled-times: ["06:00"]　世界时间 0 = 早上 6:00

安装

装起来大概十分钟

一个 jar 加两组配置，钱走 Vault，不动你现有的经济插件。

01

丢 jar

放 plugins 里启动。首次会生成 config.yml、prices.yml、messages_zh_CN.yml 和一个 sellbox.db。

02

改价格

照着 prices.yml 的格式换掉作物 id 和单价。id 要跟你在 CraftEngine 或原版里的实际 id 对上，对不上就不收。

03

先自己试一轮

给自己发一个，塞点货，debug quote 看价，debug sell 真结算一次。通了再发给玩家。

Paper 1.21+ JDK 21+ Vault + 经济插件 CraftEngine（可选） SQLite（内置） 
# config.yml 里真正要改的几段
sell:
  mode: scheduled
  scheduled-times: ["06:00"]

tax: {percent: 5.0}

decay:
  rate-per-item: 0.001
  min-factor: 0.70

daily-limit:
  reset-at: "00:00"
  tiers:
    - {min-total: 0,       amount: 50000}
    - {min-total: 300000,  amount: 200000}
    - {min-total: 1500000, amount: 500000}
    - {min-total: 4000000, amount: 1000000}

season:
  categories:
    SPRING:
      - match: "customcrops:onion*"
        multiplier: 0.8

季节那条的 * 是通配，一条盖住普通、银星、金星三种品质。 变异形态（giant_tomato 之类）的 id 不含原作物名，得单独写一条，不然它永远按 1.0 倍算。

开销

实测数字，以及唯一要注意的地方

JDK 25 加内置 SQLite，在测试机上跑出来的。写库全在异步线程，主线程只付入队成本。

路径实测说明
单笔交易的数据库入队5.6 µs可以当没有
异步写线程排空能力16,374 行/秒正常服不可能积压
打开今日收购价0.85 ms含 63 条 id × 52 条规则匹配
读累计销售额2.3–9.2 ms每个玩家只查一次，之后走内存
定时结算，200 个满箱40–160 ms会占一个 tick，见下

唯一要留意的是定时结算：到点那一瞬间会把全服箱子挨个结完，200 箱大概占 40 到 160 毫秒， 玩家会觉得顿一下。箱子过 300 就该考虑分批，或者让不同世界的结算时刻错开。 instant 模式没这问题，代价是玩家一投就卖，少了点节奏。

问答

装之前你大概会问的

不装 CraftEngine 能用吗？+

能。装了 CE 才有自定义方块外观和自定义物品识别，银星、金星、变异形态可以分开定价；不装就退化成原版方块加原版物品，价格表里把 CE 的 id 换成原版 id 就行，其余照跑。

会跟我现有的经济插件打架吗？+

不会。发钱只调 Vault 的 deposit，不接管货币、不改余额。哪天换经济插件，这边不用动。

能和商店插件一起用吗？+

能，但建议只让它负责卖。商店管买，种子、肥料、设备那些；出货箱管卖，作物回收。两边都做买卖，价格会互相打脸。

玩家离线时正好结算了怎么办？+

进待补发队列，上线自动补。也可以 /sellbox pending 查，/sellbox debug paypending 手动补。

数据怎么备份？+

就一个 sellbox.db，SQLite 加 WAL。停服拷走就行。流水默认存 90 天，log.retention-days 改长改短都行。

我只想当回收站，不想搞定时结算。+

把 sell.mode 改成 instant，投进去立刻卖。定时结算只是可选的一层，不是必须。

价格定多少才不亏？+

别按"这东西看起来值多少"定。先算玩家一分钟能收多少件、折价之后单价多少，再跟刷怪塔、挖矿、钓鱼的时薪对齐。上面那个试算器就是干这个的。

它能干什么，不能干什么

它能替掉"背一背包跑去商店点卖出"这一段，能给价格加上季节和供需，能给你一套查账工具。 它不会替你平衡经济。价格表是你定的，定歪了它只会把歪放得更大，而且放得很快。
